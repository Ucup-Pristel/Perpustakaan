# Production Migration Report — 2026-09-21

## Summary
Transisi dari Local Development → Production phase. Frontend API routing di-centralize, backend CORS di-lock, CI/CD backend auto-deploy.

## Changes

### 1. Frontend API URL Adjustment ✓
- Buat `frontend/src/lib/api.js` — export `API_URL` dinamis
  - Dev: kosong string (pakai Vite proxy `/api` → localhost:3000)
  - Prod: `https://api.edulib.id` (default VITE_API_URL kosong)
- Patch 18 fetch calls di 8 file: `AuthContext`, `Navbar`, `Home`, `Dashboard`, `SearchResults`, `AdminUpload`, `ContentList`, `Reader`
- Semua now pakai `${API_URL}/api/...` pattern
- Buat `frontend/.env.example` — dokumentasi var production

**Verified:** `npm run build` sukses, no errors.

### 2. Backend CORS & Security ✓
- Ganti `backend/server.js` cors config dari single-origin string → whitelist array
- Default: `https://edulib.id,https://www.edulib.id` (production origins)
- Support env var override: `FRONTEND_URL=https://edulib.id,https://www.edulib.id`
- Callback-based origin validation: non-browser request (curl, server-to-server) lolos standar cors lib behavior, bukan wildcard hole
- No `*` wildcard anywhere

**Verified:** `node --check backend/server.js` pass.

### 3. CI/CD Backend (GitHub Actions) ✓
- Buat `.github/workflows/deploy-backend.yml` baru
- Trigger: push main + path filter (`backend/**`, `database/**`, `package.json`)
- Action: `appleboy/ssh-action` SSH ke VPS, jalanin:
  ```
  cd /home/Perpustakaan/Perpustakaan
  git pull origin main
  npm install --production
  pm2 restart perpustakaan-api
  ```
- Secrets required (belum disetup di GitHub):
  - `SSH_HOST` — VPS IP/domain
  - `SSH_USERNAME` — SSH user (cek `~/.ssh/config` atau ask sysadmin)
  - `SSH_KEY` — private SSH key (base64 encoded atau plain PEM)

**Note:** Workflow existing `deploy.yml` (frontend) gak dirubah. Secrets `VPS_*` udah ada, gak collide.
